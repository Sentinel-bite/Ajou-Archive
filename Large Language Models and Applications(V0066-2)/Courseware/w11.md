## 一、为什么用提示词

### 从微调到提示词

自然语言处理（NLP）在过去十几年中经历了几次划时代的变革。其核心特征在于，大模型对特定任务所需标注数据量的依赖呈现指数级下降趋势：

1. **统计语言模型阶段（约 10-15 年前）**：这一时期主要通过提取大规模文本中的统计频率（如 N-Gram）来构建概率映射，几乎没有通用迁移能力。NLP 系统若要学习一个新的特定任务（如文本分类或情感分析），往往需要**数百万个特定场景的标注样本**，代价昂贵。
2. **深度神经网络与迁移学习阶段（约 10 年前）**：随着 Word2Vec、ELMo 尤其是 BERT 等预训练 Transformer 结构的出现，大模型开始通过自监督任务在海量文本上获取通用的句法语义表征。执行具体任务时，仅需将预训练模型作为基础底座，但在下游微调时仍旧需要**数千个精心标注的特定样本**。
3. **大规模生成式模型阶段（近 3 年至今）**：以 GPT-3 及其后续模型（如 GPT-4、Claude、Gemini）为代表，模型参数规模跃升了几个数量级，语料库覆盖面极广。此时，模型表现出极强的泛化特征，只需输入**一段自然语言形式的提示（Prompt）或指令**，模型就可以在不改变任何内部权重的前提下，直接输出期望的计算结果。

这一规律清晰地表明：**模型架构越庞大、预训练所使用的底层数据集越广泛，模型适应具体下游任务时对人工标注数据的物理需求量就越低。**

![语言建模简史](assets/W11_LLM_提示词工程_page_004.png)

**微调的成本**

传统上将预训练大模型适配到具体领域通常有两种主要微调手段，但都在工程中面临不同的落地门槛：

* **有监督微调（Supervised Fine-tuning, SFT）**：在模型的预训练权重基础上，针对下游具体数据集进行全量梯度反向传播。尽管它能彻底调整参数分布，但不仅需要**数万条高质量标注数据**以防模型发生严重的“灾难性遗忘”，还需要极高的算力和存储开销（因为每个下游任务都要保存一份完整的模型权重）。

![有监督微调](assets/W11_LLM_提示词工程_page_005.png)

* **参数高效微调（Parameter-Efficient Fine-tuning, PEFT）**：该技术（如 LoRA、Prefix Tuning 等）通过冻结预训练的主干网络，只微调少量插入的外接参数矩阵。这虽然解决了多任务部署时的存储冗余问题，但仍然依赖**数千条有监督标注样本**来进行迭代优化。

![参数高效微调](assets/W11_LLM_提示词工程_page_006.png)

为了跨越这个高成本微调瓶颈，研究人员引入了不依赖微调的新策略。

![为什么不需要微调](assets/W11_LLM_提示词工程_page_007.png)

**提示词的做法**

提示词机制的核心设计哲学是：**完全避免在下游任务中修改大模型的任何权重参数，转而将各种具体任务映射并重构为预训练阶段模型就已经极其熟悉的自回归文本生成问题。**

这一思想实现了彻底的**零参数更新（Zero Parameter Update）**范式。模型在其高维知识空间中本身就拥有解决多种任务的能力，设计合适的 Prompt 就像是向高维参数空间发射一个特定的“质询激活向量”，唤醒并抽取模型内部相关的泛化能力，极低成本地完成复杂的下游推理。

![提示词核心思想](assets/W11_LLM_提示词工程_page_008.png)

## 二、提示词怎么工作

### 把任务写成生成问题

为了利用纯语言生成模型解决原本是分类或判别的任务，我们需要执行“**任务重构**”。例如，在传统情感分析任务中，系统需要根据文本“这部电影太棒了”直接输出二分类概率。而在提示词范式下，我们通过模板将其改写为：“这部电影太棒了。总的来说，这部电影是 [MASK] 的。” 此时大模型只需预测 `[MASK]` 位置填入“好”还是“坏”的概率 logits 即可。通过这种将各种复杂任务重构为概率填词的机制，我们得以使用同一个语言建模接口，实现多任务的统一处理。

![任务重构为语言建模](assets/W11_LLM_提示词工程_page_009.png)

**模板与标签词**

在早期的 Prompt 与微调结合的研究中，构建了一个严谨的数学模型：

1. **模板映射 (Template mapping)**：定义了一个将输入文本 $x$ 转化为 Prompt 格式 $x_{\text{prompt}} = T(x)$ 的方式。在这个修改后的文本中，会显式留出一个填充位置 `[MASK]`。
2. **标签词映射 (Verbalizer)**：建立了一个从下游分类任务的真实分类标签空间 $\mathcal{Y}$ 到具体词汇表 $\mathcal{V}$ 的投影关系 $M: \mathcal{Y} \rightarrow \mathcal{V}$。例如映射情感标签 $y = \text{正面}$ 为词汇 $v = \text{"好"}$，标签 $y = \text{负面}$ 为词汇 $v = \text{"差"}$。
3. **条件概率估计**：根据预训练大模型在 `[MASK]` 位置生成预测词 $v$ 的似然估计，隐式计算出对应标签类别 $y$ 的概率分布：

$$P(y | x) = P(\text{[MASK]} = M(y) | T(x))$$

通过将大模型的词表输出概率进行局部归一化，即可在不接任何新分类层的前提下，计算下游分类任务的交叉熵损失，实现轻量化优化。

下图展示了典型的 Prompt 端到端推理流程：

### 模板、标签词和自动搜索

**模板设计难点**

在很长一段时间里，提示词的设计表现出了极强的偶然性。微小的提示词措辞波动，甚至是一个标点符号的删改，都会引起大模型生成结果精度的急剧跳变。由于最优的文本提示往往不符合人类的表达常理，寻找高精度模板的过程充满试错，因此这一工程方法在早期也被戏称为“黑魔法”或“提示巫术”。

![提示词工程的"黑魔法"](assets/W11_LLM_提示词工程_page_020.png)

**情感提示的局限**

近年来，研究者们（如 [arXiv:2211.01910](https://arxiv.org/abs/2211.01910)）提出了名为 **EmotionPrompt** 的情感驱动提示技术。其做法是通过在 Prompt 尾部添加包含特定人类情感暗示的短句（例如“这对我来说在学业上极其重要，请务必准确给出”“我相信你会认真对待”），来激活模型输出的注意力和一致性。

然而，这一方法也表现出了显著的**时效性衰退**。以不同版本的 OpenAI 接口为例，随着大模型在基础对齐微调和安全性训练上的强化，非情感修饰和添加了情感短句在最终数学或逻辑任务上的表现差异正在急剧缩小（如 2024 年版模型基础推理能力拉升，已使得各类“神奇咒语”带来的额外收益降为极小值）。这表明提示词设计正逐渐从“词藻技巧”回归到“清晰定义输入输出逻辑”的理性路线上。

**约束与激励实验**

在针对生成故事等“正好需要 200 字符”等特定字数与格式强约束任务的测试中，研究者分析了惩罚和正向奖励对 ChatGPT 最终指令遵循成功率的影响。

实验设计以批量生成的字符数分布均方误差（MSE）作为衡量标准：
* **惩罚设定**：威胁模型，如加入语句“如果你的回复超限或不足，系统将对你施加 10 万美元的罚款”。
* **奖励设定**：加入如“如果你完美回答，你将获得终身巧克力供应”“你会进入天堂”或“你的回答能实现世界和平”。

实验结果表明，这类情感和利益激励对大模型的表现影响差异巨大，这揭示了大模型安全对齐中复杂的隐藏偏好分布。

**自动改写与搜索**

为了克服手动写 Prompt 的不稳定性，自动化 Prompt 优化策略逐渐发展：
* **语料挖掘法**：从百万级无监督文本库中提取高概率出现的天然过渡句，用以做输入和掩码的离散桥接模板。
* **基于改写的局部搜索**：让辅助大模型基于初始 Prompt 生成多个同义改写和回译版本，构成候选池后在大规模验证集上评估以确定高分文本。
* **优化问题形式化**：利用语言模型的损失梯度来反向指导 Prompt 文本的演进与词汇筛选。

### 软提示与前缀调优

**连续向量提示**

与上述由人类词汇表中的具体字符组成的“离散 Prompt”不同，**连续提示（Continuous Prompt，或软提示 Soft Prompt）** 直接抛弃了离散文字，转而在模型的嵌入向量（Embedding）空间进行参数优化。

其代表性技术 **Prefix Tuning（前缀调优）** 的核心机制是：
* 在固定并冻结预训练语言模型所有参数 $\theta$ 的基础上，在输入向量序列前部强行拼接一个可学习的连续矩阵参数前缀 $M_\phi$。
* 优化训练时，利用下游任务的真实样本反向传播，仅对连续向量矩阵 $\phi$ 进行梯度更新：

$$\max_{\phi} \log P_{\theta, \phi}(y | x)$$

这使得前缀向量能够直接学习并收敛到高维表征空间中最优的任务控制区域，摆脱了人类词汇表的限制。

![连续提示（软提示）](assets/W11_LLM_提示词工程_page_034.png)

**软提示的优势**

软提示相比普通的硬文本提示，展现出更强的工程优势：
1. **解除了表达离散限制**：离散词表的大小是有限的，人类无法找到完美的文字组合来对齐复杂的任务。连续的软向量是实数向量，拥有几乎无限的参数表达和调优空间。
2. **自适应与收敛效率高**：软提示的前缀向量完全可以通过神经网络的梯度迭代自动逼近并收敛到最精准的解，避开了人工设计时的不确定性，在执行特定且稳定的业务场景（如持续机器翻译、客服意图识别）时，展现了极高的稳定性。

![为什么软提示有效](assets/W11_LLM_提示词工程_page_035.png)

## 三、少样本与上下文学习

### 示例学习

**Few-shot Prompting（少样本提示）** 是上下文学习的最核心表现。当我们需要模型执行某个特定任务（例如英译汉或生成 SQL）时，我们只需在 Prompt 头部塞入少量的“问题-答案”具体演示示例（Demonstrations），大语言模型便能模仿并遵循这一前置模式，输出类似格式的最终答案。在此期间，完全不需要执行任何反向传播参数微调。

```
问题：法国的首都是？ 答案：巴黎
问题：德国的首都是？ 答案：柏林
问题：英国的首都是？ 答案：____
```

![少样本提示原理](assets/W11_LLM_提示词工程_page_036.png)

这种从前置输入示例中学习的能力，被称为 **In-Context Learning (ICL, 上下文学习)**。大模型就像是一个通用的多功能机器，通过在提示词中“展示”具体的业务输入，即可即时完成泛化重塑。

![少样本提示与上下文学习](assets/W11_LLM_提示词工程_page_037.png)

### 规模和顺序影响

上下文学习绝非大模型与生俱来的通用本领，它表现出了一种显著的**涌现能力（Emergent Ability）** 特性。TriviaQA 的实验数据表明：
* 在参数量低于 10B 的较小模型上，即使在上下文中不断增加少样本示例的个数，其预测准确率也提升有限。
* 当模型的参数规模（Scale）跨越某个临界阈值（如大于 100B）后，随着 Few-shot 示例数量的递增，模型的任务表现会出现爆发式的越级跃升。这揭示了大规模知识存储和自注意力泛化是驱动上下文学习的基石。

![冷知识竞赛示例](assets/W11_LLM_提示词工程_page_038.png)

![规模对上下文学习的影响](assets/W11_LLM_提示词工程_page_039.png)

**示例顺序和格式**

在 GPT-3 初生的早期，上下文学习饱受以下问题的困扰：
* **顺序极其敏感**：调整 Few-shot 中那 3 个例子展示的先后顺序，准确率可能会产生 20% 以上的离奇波动。
* **幻觉干扰**：对格式约束不敏感，极易偏离期望输出。
而现代模型（如 GPT-4、Claude 3.5）通过在 RLHF 阶段针对指令跟随（Instruction-Following）能力的深度拉齐，对示例格式的容错力得到了质的飞跃，使少样本提示具有了真正的工程可用性。

![GPT-3 时代的三大问题](assets/W11_LLM_提示词工程_page_040.png)

![现代模型的改进](assets/W11_LLM_提示词工程_page_041.png)

**为什么示例会生效**

在理论层面上，上下文学习为什么能够在不修改权重的情况下完成“即时学习”？

最新的数学理论（如 [arXiv:2211.16616](https://arxiv.org/abs/2211.16616)）给出了令人信服的解释：**Transformer 的自回归前向传播可以被隐式地视为执行了一次“元梯度下降（Meta-Gradient Descent）”**。在计算自注意力时，当前 Query 通过与上下文中的 $K$ 和 $V$ 交互，在数学上等价于利用前置少样本示例提供的约束信号，对模型当前的隐空间表征进行了一次隐式的误差反向校正和状态迁移。这意味着，虽然物理模型参数保持冻结，但当前计算在隐空间内动态完成了相当于“前向参数微调”的计算效果。

## 四、复杂推理提示

### 思维链与任务分解

面对算术题、数学逻辑等高难度任务，直接要求模型给出答案往往会导致计算失败。为了克服这个问题，Wei 等人提出了以下优化方案：

* **逐步引导 (Step-by-Step)**：在提示中加入简单的命令“**让我们一步步来思考 (Let's think step by step)**”。这一简单的引导会促使大模型将原本一步到位的直接概率猜测，转化为按步骤的序列逐步推导，大幅降低了思维跳跃带来的精度错乱。

![逐步引导](assets/W11_LLM_提示词工程_page_044.png)

![Step-by-Step 效果](assets/W11_LLM_提示词工程_page_045.png)

* **Chain-of-Thought (CoT, 思维链提示)**：在少样本示例中，故意写入**包含详细中间推理步骤的完整心路历程（Self-explanation Demonstrations）**。大模型通过学习和模仿这些演示步骤，在其后的新问题前向生成中，也会强制自己先输出一连串详尽的逻辑推理链条，最后再得出最终答案。思维链极大提升了模型解决复杂多步骤逻辑任务的能力。

![CoT 思维链提示法](assets/W11_LLM_提示词工程_page_046.png)

![CoT 示例 (1)](assets/W11_LLM_提示词工程_page_047.png)

![CoT 示例 (2)](assets/W11_LLM_提示词工程_page_048.png)

![CoT 推理过程详解](assets/W11_LLM_提示词工程_page_049.png)

**从简单问题开始**

当问题复杂度过高以至于思维链也会发生推理漂移时，**Least-to-Most Prompting (LtM, 从最少到最多提示)** 表现出了极强的策略优越性。它将计算显式分为两个独立的交互阶段：
1. **分解阶段 (Decomposition)**：输入问题，强制大模型将其拆解为一系列难度由浅入深的子问题序列。
2. **递进求解阶段 (Sub-question Solving)**：从最简单的子问题开始计算，将前一步生成的答案作为上下文信息动态馈送到下一步中，层层递推，直到解出最复杂的终极目标。

LtM 架构极大地减轻了多跳推理时大模型上下文注意力衰减的问题。

### 程序辅助与一致性

即便有了 CoT 的推理链条，大模型仍然经常卡在繁琐的具体浮点数运算上。**Program-of-Thought (PoT, 程序思维提示)** 从工程层面给出了新颖的解法：它并不要求模型用自然语言写出计算结论，而是引导大模型**生成一段用于解题的 Python 计算代码**。接着，系统在沙箱中调用 Python 解释器执行该段代码，并将计算返回的精准数值合并到最终输出中。这结合了大模型的逻辑拆解能力和代码解释器的精确运算能力，达成了几乎 100% 的数学计算正确率。

![程序思维 PoT](assets/W11_LLM_提示词工程_page_051.png)

**一致性检查**

为了防范推理链路发生无序的随机偏离，可以采用以下一致性保障策略：

* **Faithful CoT (可信思维链)**：通过限制推理步骤的产生格式（如遵循严谨的一阶谓词逻辑或者特定的半结构化表示），确保中间的每一步推导都是逻辑紧密相扣且忠实于最终结论的，避免满嘴胡话导致计算崩盘。

![Faithful CoT](assets/W11_LLM_提示词工程_page_052.png)

* **Self-Consistency (自洽性投票机制)**：这是一种与具体提示设计正交的系统级增强手段。在处理问题时，系统会多次采样（例如设定较高的 Temperature，让同一个 CoT Prompt 多次生成 20 条不同的推理轨迹和答案候选）。最后，系统对这 20 个答案候选进行**多数投票（Majority Voting）**。取出现概率最高的答案作为系统的最终输出。这种集成的思想，能够极大稀释掉由于偶然随机采样引起的单个推理步骤出错导致的坏例率。
