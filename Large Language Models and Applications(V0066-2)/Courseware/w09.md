## 一、注意力为什么会慢

### 自回归生成与推理阶段

在生成式大语言模型（LLM）的推理阶段，模型通常采用自回归（Autoregressive）模式进行文本生成。这意味着模型在生成序列时是“逐字”或“逐 token”进行的。具体来说，模型每次根据当前的输入序列预测下一个 token，并将其拼接至序列末尾，作为下一步的输入。在这个过程中，每产生一个新的 token，模型都需要对其与之前所有已生成的历史 token 进行自注意力（Self-Attention）计算，以捕捉长距离的上下文关联。

![语言模型自回归生成示意](assets/W9_LLM_FLASHATT_page_003.png)

自注意力机制的数学核心是将输入映射为 Query（查询）、Key（键）和 Value（值）三个矩阵。在推理阶段，对于当前新生成的 query 向量 $q$，我们需要与序列中所有已生成位置的 key 向量 $k_j$ 计算点积以获取注意力得分，再通过 Softmax 函数进行归一化，最后加权求和对应的 value 向量 $v_j$ 得到输出 $o$。

以序列长度为 4 的简易场景为例，其自注意力计算步骤如下：
1. **计算注意力分数**：计算当前 query 与历史 key 的相似度，$s_{1,j} = q_1 \cdot k_j$（其中 $j = 1,2,3,4$）。
2. **执行 Softmax 归一化**：通过对分数取指数并归一化，得到注意力权重概率分布 $s'_{1,j} = \text{softmax}(s_{1,j})$。
3. **加权求和输出**：使用权重对对应的 Value 向量进行加权求和，生成当前步骤的最终表征 $o = \sum_j s'_{1,j} \cdot v_j$。

![自注意力计算过程](assets/W9_LLM_FLASHATT_page_004.png)

**Prefill 与 Decode 阶段**

大语言模型的推理过程主要包含两个相互独立的阶段，每个阶段的计算特性截然不同：

* **Prefill（预填充）阶段**：发生在输入 prompt 刚被送入模型的时候。此时模型需要一次性处理整个 prompt（例如用户输入的“今天天气真”），并并行计算所有位置的 Key 和 Value 向量，将其存入显存中。此阶段的并行度高，计算效率相对较好。
* **Decode（解码）阶段**：在 prompt 处理完毕后，模型开始逐个生成后续 token（如“暖” $\rightarrow$ “和” $\rightarrow$ `[END]`）。在 Decode 阶段的每一步中，模型只需要针对最新生成的一个 token 计算其 Query 向量，然后与之前缓存在显存中的历史 KV 向量进行注意力计算。

随着文本生成的不断进行，历史序列长度 $N$ 呈线性增长，这导致 KV 缓存的矩阵体积极速膨胀。每一次自注意力计算的计算量和显存占用随之节节攀升。这也是大模型在长文本场景下面临的核心性能瓶颈。

![Prefill 与 Decode 阶段](assets/W9_LLM_FLASHATT_page_005.png)

### GPU 访存瓶颈

**GPU 存储层级**

要理解注意力机制性能瓶颈的本质，必须深入 GPU 的硬件存储架构。现代 GPU 并非单一的存储空间，而是采用了“越靠近计算核心速度越快、容量越小”的分层存储体系：

1. **Register（寄存器）**：直接服务于计算核心，读写延迟极低，但容量微乎其微（通常仅为 KB 级别），仅用于存放临时计算变量。
2. **SRAM（片上高速缓存）**：靠近计算单元，速度极快（如 A100 GPU 的片上 SRAM 带宽高达约 19 TB/s），但容量极小（通常在 20 MB 左右），常用于存放共享内存（Shared Memory）和一级缓存。
3. **HBM（高带宽显存）**：我们常说的 GPU 显存，容量较大（如 A100 的 40GB/80GB），但带宽相对 SRAM 而言非常有限（约 1.5 - 2 TB/s）。

可以看出，SRAM 与 HBM 之间存在着接近 10 倍的巨大带宽鸿沟。如果计算单元频繁从慢速的 HBM 读取数据，就会导致计算核心处于闲置等待状态，限制了硬件的吞吐量。

![GPU 分层存储结构](assets/W9_LLM_FLASHATT_page_008.png)

![GPU 存储架构详细示意](assets/W9_LLM_FLASHATT_page_009.png)

**标准注意力的读写开销**

在传统的注意力机制（Standard Attention）计算中，GPU 会执行以下逻辑：
1. 从 HBM 中将 $Q$ 和 $K$ 矩阵加载到 SRAM $\rightarrow$ 在 SRAM 中执行矩阵乘法得到 $S = QK^T$ $\rightarrow$ **将大小为 $N \times N$ 的中间得分矩阵 $S$ 写回 HBM**。
2. 从 HBM 读取 $S$ 加载到 SRAM $\rightarrow$ 执行 Softmax 归一化操作得到 $P = \text{softmax}(S)$ $\rightarrow$ **将大小为 $N \times N$ 的注意力概率矩阵 $P$ 写回 HBM**。
3. 从 HBM 中读取 $P$ 和 $V$ 加载到 SRAM $\rightarrow$ 执行矩阵乘法得到最终的注意力输出 $O = PV$ $\rightarrow$ 将 $O$ 写回 HBM。

![Attention 在 GPU 上的计算流程](assets/W9_LLM_FLASHATT_page_007.png)

![标准 Attention IO 流程详细示意](assets/W9_LLM_FLASHATT_page_011.png)

深度学习中的计算算子通常被分为两类：
* **计算受限（Compute-bound）**：瓶颈在于 GPU 的算力，例如大规模矩阵乘法。这类计算会充分利用 Tensor Core，硬件利用率高。
* **内存带宽受限（Memory-bandwidth bound）**：瓶颈在于 HBM 数据的读写速度，而非计算本身。例如 Softmax、Dropout、LayerNorm。

标准注意力算法慢的根本原因正在于此：对于长度为 $N$ 的序列，中间矩阵 $S$ 和 $P$ 的空间复杂度达到 $O(N^2)$。以 $N=4096$ 为例，仅单个 Head 的 $S$ 矩阵在 FP16 精度下就占据了大约 32 MB 显存，远超 SRAM 的容量。为了完成计算，GPU 必须频繁地在慢速的 HBM 和快速的 SRAM 之间进行 $O(N^2)$ 级别数据的多次写回和读取。这种高额的 IO 带宽消耗，使得原本计算密集的注意力层退化成了典型的内存带宽受限算子。

![传统 Attention 为什么慢](assets/W9_LLM_FLASHATT_page_010.png)

## 二、Flash Attention 的思路

### 分块计算

为了突破显存读写瓶颈，Flash Attention（[arXiv:2205.14135](https://arxiv.org/abs/2205.14135)）引入了两个关键的工程创新：**分块计算（Tiling）**与**在线 Softmax（Online Softmax）**。

其基本思路是：
1. **舍弃在全局 HBM 中存储 $N \times N$ 的中间矩阵**。
2. 将输入序列切割成若干个较小的数据块（Blocks），使其能够完美容纳在高速的片上 SRAM 中。
3. 利用在线 Softmax，一边读取 KV 分块一边计算并更新注意力结果，在不把中间矩阵写回 HBM 的前提下，完成整个注意力的计算。

通过“**用计算换访存**”的逻辑——虽然增加了局部的计算步骤，但由于避免了海量数据在快速 SRAM 和慢速 HBM 之间的频繁搬运，从整体上大幅度缩减了推理和训练的时间。

### 在线 Softmax

常规的 Softmax 工程实现（Safe Softmax）为了保证数值稳定性，必须先减去向量中的最大值以防指数运算发生上溢：

$$\text{softmax}(x_i) = \frac{e^{x_i - x_{\max}}}{\sum_{j=1}^{L} e^{x_j - x_{\max}}}$$

这就要求对数据进行两轮完整遍历：第一轮扫描所有元素找到最大值 $x_{\max}$，第二轮计算指数和及概率分布。

![Softmax 数学定义](assets/W9_LLM_FLASHATT_page_013.png)

![Softmax 工程实现示例](assets/W9_LLM_FLASHATT_page_014.png)

**Online Softmax** 改变了这一模式，它支持**一边读取数据一边递推地更新最大值和分母累积和**。其核心机制在于引入了“**校正因子**”。当处理新分块并发现更大的局部最大值 $m_{\text{new}}$ 时，算法会通过乘以 $e^{m_{\text{old}} - m_{\text{new}}}$ 来动态缩放和修正之前已经计算出来的部分分母和输出累加。这确保了在只进行单次遍历的条件下，依然能获得与标准 Safe Softmax 数学完全一致的精确结果。

![Online Softmax 计算图解 - 步骤 1](assets/W9_LLM_FLASHATT_page_015.png)

![Online Softmax 计算图解 - 步骤 2](assets/W9_LLM_FLASHATT_page_016.png)

这种单次遍历与局部递推特性，为在 SRAM 内部实现切块级自注意力提供了数学上的可能性。

## 三、分块递推怎么算

### 从直觉到公式

我们可以用一个形象的比喻来理解分块计算的逻辑：
* **HBM** 类似于一个容量巨大但路途遥远、搬运缓慢的“**主仓库**”。
* **SRAM** 则是靠近工位、容量狭小但伸手可得的“**临时工作台**”。

如果每一次装配（计算）都需要把仓库里的所有原料（整个得分矩阵）全部搬到工作台上堆放，工作台就会因为溢出而瘫痪，且来回跑腿（读写 IO）会浪费大量时间。更好的策略是，每次只从仓库中搬运一小箱零件（切片块）到工作台上，在工作台上快速完成局部组装，并将局部状态进行更新，直到处理完全部原料。

![仓库与工作台类比](assets/W9_LLM_FLASHATT_page_031.png)

**Softmax 分块递推**

如果将一个长为 $L$ 的注意力分数向量切分为 $B$ 个长度为 $N$ 的块，传统的 Softmax 分母可以展开写成各个分块局部指数和的求和：

$$\sum_{i=1}^{L} e^{a_i - a_{\max}} = \sum_{k=1}^{B} \left( \sum_{i \in \text{Block}_k} e^{a_i - a_{\max}} \right)$$

为了消除对全局最大值 $a_{\max}$ 的即时依赖，在处理第 $k$ 个分块时，我们假设当前见到的局部最大值 $d_k$ 就是“暂时的全局最大值”。

![Softmax 分块展开](assets/W9_LLM_FLASHATT_page_032.png)

![分块 Softmax 详细推导](assets/W9_LLM_FLASHATT_page_033.png)

当算法递推到第 $k$ 块并得到新的局部最大值 $d_k = \max(d_{k-1}, \max(\text{Block}_k))$ 时，旧的指数累积和 $S_{k-1}$ 会被校正因子修正：

$$S_k = S_{k-1} \cdot e^{d_{k-1} - d_k} + \sum_{i \in \text{Block}_k} e^{a_i - d_k}$$

通过这种逐步修正的形式，我们在处理每个切片时无需预知全局最大值，从而摆脱了全局依赖。

![消除全局最大值依赖](assets/W9_LLM_FLASHATT_page_034.png)

![分块 - 假设局部最大值为全局最大值](assets/W9_LLM_FLASHATT_page_035.png)

![分块递推推导 - 步骤 1](assets/W9_LLM_FLASHATT_page_036.png)

![分块递推推导 - 步骤 2](assets/W9_LLM_FLASHATT_page_037.png)

### 输出累积

同样的修正逻辑被推广到注意力最终输出矩阵 $O = PV$ 的累积计算中。在每个分块迭代中，我们不仅要更新分母 $l_k$ 和最大值 $m_k$，还要实时修正未归一化的累加结果 $O_k$。

对于每一个输入的分块 $k$，Flash Attention 遵循以下严格的数学递推式：

1. **计算局部得分**：$s_k = Q \cdot K_k^T$
2. **计算并更新局部最大值**：$m_k = \max(m_{k-1}, \max(s_k))$
3. **计算并累积指数和（带校正因子）**：$l_k = e^{m_{k-1} - m_k} \cdot l_{k-1} + \sum e^{s_k - m_k}$
4. **计算并更新局部注意力输出累加值（带校正因子）**：$O_k = e^{m_{k-1} - m_k} \cdot O_{k-1} + e^{s_k - m_k} \cdot V_k$
5. **归一化输出**：在完成所有 $B$ 个分块计算后，执行 $O_{\text{final}} = O_B / l_B$ 得到最终与标准 Attention 完全等价的归一化矩阵。

## 四、效果与实现

### 流程对比和例题

我们可以对比传统方法与分块算法在数据读写开销上的表现：

* **标准 Attention**：从 HBM 加载 $Q, K, V$，每次中间矩阵乘法或 Softmax 计算都要把临时生成的 $S, P$ 矩阵写回并重新读取自 HBM。每次都会带来 $O(N^2)$ 的物理空间占用和极高的总线带宽开销。
* **Flash Attention**：仅从 HBM 分块读取 $Q, K_k, V_k$ 到片上 SRAM，在 SRAM 内部高效完成局部得分计算、局部最大值比较及指数和递推，且在整个运行过程中**完全不向 HBM 写回任何 $N \times N$ 的中间值**，最终输出直接回写到 HBM。

### 性能表现

**实验结果**

在基准评测（Benchmarks）中，Flash Attention 表现出了极强的吞吐加速和极其显著的显存节省效果：

* **训练与推理加速**：在主流的长序列配置下（如 $N \ge 1024$ ），Flash Attention 可以带来 **2x 到 4x** 的端到端执行效率提升。
* **显存容量优化**：由于摆脱了对 $O(N^2)$ 的中间注意力概率分布的物理存储依赖，显存使用空间复杂度直接从二次方级别 $O(N^2)$ 降低到了一次线性级别 $O(N)$。这极大释放了显存容量，使得大模型训练与长文本（例如支持 100K 甚至百万上下文）的生成推理成为可能。
* **规模效益**：随着待计算的上下文长度 $N$ 越来越长，Flash Attention 展现的加速比就越发明显，因为避免往返搬运的 $O(N^2)$ 数据流量呈几何级增长。
