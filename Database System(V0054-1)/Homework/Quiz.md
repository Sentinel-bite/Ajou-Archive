### 1. 下列哪一项最能准确描述数据库系统的核心任务？

- **A. 提供一个高效且方便管理数据的环境 (正确)**
- B. 仅用于存储海量数据
- C. 仅用于单用户环境
- D. 只能处理只读数据

> **【选项解析】**：B 错在“仅用于存储”，数据库不仅仅是硬盘，更重要的是管理；C 错在现代 DBMS 都是为高并发多用户设计的；D 错在数据库支持增删改查（DML）。
>
> **【知识点扩展】**：DBMS 的全称是 Database Management System。它出现的根本目的就是为了克服早期文件系统的弊端，提供安全性、并发控制、崩溃恢复和高效的查询机制。

### 2. 在数据库体系结构中，存储管理器的主要职责是？

- A. 执行所有交易的提交与回滚
- B. 实现应用程序的业务逻辑
- **C. 在数据库内部与操作系统文件管理器之间提供接口，负责高效存取数据 (正确)**
- D. 替数据库用户进行权限认证

> **【选项解析】**：A 是事务管理器的职责；B 是应用层（中间层）的职责；D 属于授权与完整性管理器。C 完美描述了 Storage Manager 的核心定义。
>
> **【知识点扩展】**：存储管理器（Storage Manager）是引擎的底层核心，它必须管理缓冲区（Buffer）、文件存放，并在内存和磁盘之间高效搬运数据块。

### 3. 数据定义语言（DDL）在数据库中主要用于?

- A. 访问控制和授权管理
- **B. 定义和修改数据库模式及结构 (正确)**
- C. 执行数据查询
- D. 编写应用程序逻辑

> **【选项解析】**：A 虽然 DDL 包含部分授权，但不是主要目的；C 是 DML (Data Manipulation Language) 的任务；D 是宿主编程语言的任务。
>
> **【知识点扩展】**：DDL 就像是建筑师的图纸，包括 `CREATE`, `ALTER`, `DROP`。执行 DDL 后，系统会更新“数据字典（Data Dictionary）”中的元数据。

### 4. 数据库设计中的”物理数据独立性“指的是？

- A. 物理存储结构与可视化界面绑定在一起
- B. 改变数据库的逻辑模式以提升性能
- C. 只影响数据字典中的元数据
- **D. 在不改变逻辑模式的前提下修改物理存储结构 (正确)**

> **【选项解析】**：A 描述反了，独立性意味着解绑；B 描述的是逻辑数据独立性。D 正确，即“底层换磁盘/加索引，上层表结构和代码不用改”。
>
> **【知识点扩展】**：这是数据库三层抽象（物理层、逻辑层、视图层）带来的最大优势，极大降低了应用程序维护的成本。

### 5. 在关系数据库中，SQL 的性质最接近下列哪一项？

- A. 仅能进行数据写入而不能查询
- B. 完备的通用编程语言
- **C. 非过程性查询语言 (声明式语言) (正确)**
- D. 需要逐步指明数据如何获取的语言

> **【选项解析】**：B 错在 SQL 不是图灵完备的，无法写无限循环；D 描述的是过程性语言（如 C, Java）。SQL 只需要告诉引擎“我要什么结果”，所以是非过程性（声明式）的。
>
> **【知识点扩展】**：由于纯 SQL 缺乏通用计算能力，因此在实际开发中，通常会将 SQL 嵌入到宿主语言（Host Language）中使用，或通过 JDBC/ODBC 连接。

### 6. 下列哪一项最能体现三层架构中应用程序与数据库的关系？

- A. 应用层直接实现数据存储在本地文件系统（两层架构）
- **B. 客户端-应用服务器-数据库系统的分层通信 (正确)**
- C. 单一应用直接访问数据库的模型
- D. 客户端直接访问存储管理器实现数据写入

> **【选项解析】**：A 和 C 描述的是两层架构或单体架构；D 违背了系统封装和安全原则。B 是标准的三层架构。
>
> **【知识点扩展】**：三层架构 (3-Tier) 将表现层（UI）、业务逻辑层（App Server）和数据访问层（Database）分离开来。现代绝大多数 Web 应用均采用此架构以提升安全性和可扩展性。

### 7. 关系模型中，数据库中的数据通常以哪种单位进行组织？

- A. XML节点树
- **B. 表（关系） (正确)**
- C. 图（Graph）
- D. 键值（key-value）对集合

> **【选项解析】**：A 是半结构化模型；C 是图数据库；D 是 NoSQL 键值数据库。B 是关系型数据库的核心数据结构。
>
> **【知识点扩展】**：在关系模型中，二维表在数学上被称为“关系 (Relation)”，表中的列称为“属性 (Attribute)”，行称为“元组 (Tuple)”。

### 8. 数据冗余和不一致性是早期文件系统的主要问题，数据库系统通过什么来解决这个问题？

- **A. 数据的集中管理 (正确)**
- B. 增加存储容量
- C. 分布式存储
- D. 代码的复用

> **【选项解析】**：B 只解决物理空间问题；C 可能会加剧不一致；D 属于软件工程代码层面的概念。A 通过集中存储与关联映射解决冗余。
>
> **【知识点扩展】**：早期按部门独立建立文件系统会导致同一个人的数据在多处保存，一旦更新不同步就会出现“不一致”。DBMS 的中心化管理完美避开了这点。

### 9. 在数据库管理系统中，哪个组件负责用户与数据之间的交互？

- A. 数据字典
- B. 存储管理器
- C. 事务管理器
- **D. 查询处理器 (正确)**

> **【选项解析】**：A 存储元数据；B 负责底层磁盘和内存交互；C 负责并发和故障恢复。D 包含 DML 编译器和引擎，直接接收并解析用户的 SQL 请求。
>
> **【知识点扩展】**：查询处理器 (Query Processor) 是大脑，它负责理解 SQL 语法、进行逻辑优化，并选择代价最低的路径去指挥存储管理器拿数据。

### 10. 哪种约束确保一个表中的某一列的值是唯一的？

- A. 外键约束
- B. 非空约束
- **C. 主键约束 (正确)**
- D. 类型约束

> **【选项解析】**：A 用于表间关联；B 只保证不为 NULL；D 限制数据格式。C 主键强制列值唯一且非空。
>
> **【知识点扩展】**：主键 (Primary Key) 是被数据库设计者显式选中的候选键，作为元组的唯一标识符。一个表只能有一个主键。

### 11. 在关系代数中，哪个操作用于选择符合某个条件的元组（行）？

- **A. 选择操作（**$\sigma$**） (正确)**
- B. 并集操作（$\cup$）
- C. 连接操作（$\bowtie$）
- D. 投影操作（$\Pi$）

> **【选项解析】**：B 用于合并表；C 用于横向拼接表；D 用于挑选列。A ($\sigma$) 专门用于基于特定逻辑条件对行进行过滤。
>
> **【知识点扩展】**：选择操作对应于 SQL 中的 `WHERE` 子句。它接收一个关系，并输出一个包含了符合特定条件行的新关系。

### 12. 在关系代数中，当你要把两个相同结构关系的元组合并成一个新关系时，最有可能使用哪个操作？

- A. 选择操作（$\sigma$）
- **B. 联合操作（**$\cup$**） (正确)**
- C. 笛卡尔积（$\times$）
- D. 差集操作（$-$）

> **【选项解析】**：A 是单表过滤；C 会产生宽表；D 是找不同。B (联合/并集) 用于将同结构的表上下合并并自动去重。
>
> **【知识点扩展】**：联合操作要求两个关系具有相同的元数（列数相同）且对应列的属性域兼容。对应 SQL 的 `UNION`。

### 13. 外键约束的作用是？

- **A. 确保一个关系中的值出现在另一个关系的主键中 (正确)**
- B. 用于删除行
- C. 用于排序
- D. 替数据库用户进行权限认证

> **【选项解析】**：外键的核心定义就是引用完整性（Referential Integrity），即 A 选项。
>
> **【知识点扩展】**：外键防止了“孤儿数据”的产生。例如，选课表中出现的学生 ID 必须在学生档案表的主键 ID 中真实存在。

### 14. 关系是无序的，这意味着:

- A. 关系必须有主键
- B. 列的顺序可以任意
- **C. 行的顺序不会影响结果 (正确)**
- D. 元组必须按ID排序

> **【选项解析】**：在关系理论中，关系是一组元组的“集合（Set）”。数学集合中的元素没有先后顺序之分，因此 C 正确。
>
> **【知识点扩展】**：在没有写 `ORDER BY` 的情况下，数据库返回数据的顺序是随机且不可靠的，不应依赖默认的输出顺序来编写业务逻辑。

### 15. 连接操作（$\bowtie_{\theta}$）本质上是在做什么?

- **A. 笛卡尔积 + 选择 (正确)**
- B. 投影 + 笛卡尔积
- C. 投影 + 并集
- D. 只进行并集

> **【选项解析】**：关系代数中，$r \bowtie_{\theta} s = \sigma_{\theta}(r \times s)$。也就是先穷举所有组合（笛卡尔积），再筛选满足条件的（选择）。
>
> **【知识点扩展】**：理论上是先乘积再筛选，但在实际执行中，优化器会使用 Hash Join 或 Merge Join 算法，而避免直接生成庞大的笛卡尔积中间表。

### 16. 如果需要使用一个字段对结果进行分组，应该使用哪个SQL子句？

- A. WHERE 子句
- **B. GROUP BY 子句 (正确)**
- C. HAVING 子句
- D. ORDER BY 子句

> **【选项解析】**：A 过滤单行；C 过滤聚合组；D 负责最终排序；B 专门用于根据指定列将行数据划分为多个小组。
>
> **【知识点扩展】**：`GROUP BY` 的出现往往伴随着聚合函数 (`SUM`, `AVG`, `COUNT` 等)。它将数据集中具有相同分组键值的多行压缩成单行。

### 17. 在 SQL 的 WITH 子句中，可以定义什么？

- A. 并行关系
- B. 引用关系
- **C. 临时关系（公共表表达式 CTE） (正确)**
- D. 附属关系

> **【选项解析】**：WITH 子句用于定义在当前查询生命周期内有效的临时视图/关系（Common Table Expression, CTE）。
>
> **【知识点扩展】**：CTE 极大地提升了复杂 SQL 的可读性。通过为中间子查询步骤命名，避免了深层嵌套导致的代码难以维护。

### 18. 以下哪个查询会正确返回所有讲师的姓名及其所属的房间信息，前提是 department 表与 instructor 通过 dept_name 关联？

- A. SELECT i.name, d.building FROM instructor i LEFT JOIN department d ON i.dept_name = d.name;
- B. SELECT name FROM instructor, department WHERE instructor.dept_name = department.name;
- **C. SELECT i.name, d.building FROM instructor i, department d WHERE i.dept_name = d.dept_name; (正确)**
- D. SELECT name, building FROM instructor JOIN department WHERE instructor.dept_name = department.dept_name;

> **【选项解析】**：A 使用了左连接可能多出未分配部门的人且键名不准；B 漏了房间信息列；D 显式 JOIN 应配合 ON 而非 WHERE；C 是最经典的基于笛卡尔积加选择的隐式内连接语法。
>
> **【知识点扩展】**：在 `FROM` 子句中用逗号隔开多张表，并在 `WHERE` 中指定主外键相等的条件，是 SQL-89 标准典型的表连接写法。

### 19. 在不使用 FROM 子句的情况下，SELECT 语句在标准或支持的 SQL 系统中通常可以返回哪类结果？

- A. SELECT 1+1; 必然返回一个报错信息
- B. SELECT 1 AS ONE, 2 AS TWO; 返回两列两行
- **C. SELECT '437' AS FOO; 结果是单列单行，值为 '437' (正确)**
- D. SELECT *; 依然可以返回所有环境遍历

> **【选项解析】**：在很多现代数据库中，无 FROM 子句查询常量是合法的，它只会返回包含所选常量表达式的“1行结果”。
>
> **【知识点扩展】**：如果在 SELECT 后添加常量但跟了 FROM 子句，则该常量会被映射为表中的总行数（针对表的每一行输出一次该常量）。

### 20. 哪一个查询能按部门名称排序后返回每个部门的讲师姓名？

- **A. SELECT name FROM instructor ORDER BY dept_name; (正确)**
- B. SELECT dept_name, name FROM instructor ORDER BY dept_name, name;
- C. SELECT DISTINCT dept_name, name FROM instructor;
- D. SELECT name, dept_name FROM instructor ORDER BY name;

> **【选项解析】**：题目要求返回讲师姓名并按部门名称排序，A 完全符合。B 多输出了列并加了姓名二级排序；D 是按姓名排序。
>
> **【知识点扩展】**：`ORDER BY` 是 SQL 引擎执行的最后一个步骤，隐藏列（未出现在 SELECT 中）也可以用作排序键。

### 21. 若要仅查看讲师的姓名且去重，应该使用哪条语句？

- **A. SELECT DISTINCT name FROM instructor; (正确)**
- B. SELECT name FROM instructor;
- C. SELECT UNIQUE name FROM instructor;
- D. SELECT DISTINCT dept_name FROM instructor;

> **【选项解析】**：强制消除结果集中的重复行必须使用 `DISTINCT` 关键字。`UNIQUE` 在标准 SQL 中用于 DDL 约束或测试。
>
> **【知识点扩展】**：SQL 默认使用多重集（Multiset）语义保留重复以省去排序开销。只有显式添加 `DISTINCT` 才会执行去重逻辑。

### 22. 若要找出薪水在 70000 以上的讲师的姓名，应该写成哪种形式？

- A. SELECT salary FROM instructor WHERE name > 70000;
- **B. SELECT name FROM instructor WHERE salary > 70000; (正确)**
- C. SELECT name FROM instructor WHERE dept_name = 'Comp. Sci.';
- D. SELECT name FROM instructor HAVING salary > 70000;

> **【选项解析】**：目标是“姓名”(SELECT name)，条件是“薪水大于70000”(WHERE salary > 70000)。D 错在单行数据的条件过滤不能用 HAVING。
>
> **【知识点扩展】**：`WHERE` 子句不仅可以进行大小比较，还支持逻辑运算 (`AND`, `OR`, `NOT`) 以及通过 `BETWEEN` 进行区间筛选。

### 23. 要把讲师的工资月薪显示为 monthly_salary，正确的写法是哪一个？

- A. SELECT id, name, monthly_salary = salary/12 FROM instructor;
- B. SELECT id, name, salary/12 FROM instructor;
- **C. SELECT id, name, salary/12 AS monthly_salary FROM instructor; (正确)**
- D. SELECT id, name, salary / 12 AS salary_per_month FROM instructor;

> **【选项解析】**：为输出列或计算表达式重命名，必须使用 `AS` 关键字（不能用等号）。D 选项命名不符题意。
>
> **【知识点扩展】**：`AS` 别名不仅能美化输出结果的表头，在复杂查询和表连接中，别名是解决同名冲突和指代上下文的必备手段。

### 24. 考虑以下查询: SELECT id, name, salary FROM instructor ORDER BY dept_name, salary DESC；下列说法正确的是？

- A. 结果按 dept_name 的长度排序,再按 salary 降序排序
- B. 结果先按 dept_name 降序分组,然后按照id 的先后顺序再按 salary 降序排序
- C. dept_name 的大小写会影响排序顺序
- **D. 结果先按 dept_name 升序排列，同一个 dept_name 内的行再按 salary 降序排列 (正确)**

> **【选项解析】**：多列排序时按照书写顺序确定优先级。`dept_name` 没有带 DESC，默认升序（ASC）。所以先按部门排，同部门内按薪水降序。
>
> **【知识点扩展】**：多级排序在生成报表时非常常见，数据库引擎会依次对比后续的排序键来打破前一个排序键遇到相等值时的平局。

### 25. 下列关于集合运算的说法最佳的描述是？

- **A. 集合运算在执行前要求参与的关系具有相同的元数（列数）和兼容的属性域 (正确)**
- B. 集合运算只能在同一张表的不同列之间使用,不能用在两张表上
- C. 集合运算不会自动消除重复项,所以需要添加额外的操作把重复项去除
- D. 集合运算的结果会产生一个和任意输入关系完全相同的模式并保存数据

> **【选项解析】**：B、C、D 的陈述全部违背了集合运算的特性。A 准确描述了参与集合运算的严格前提条件（类型兼容性）。
>
> **【知识点扩展】**：“元数 (Arity)” 指的是关系中列的数量。如果一个表有 3 列，另一个有 2 列，则它们绝不可能进行并、交、差运算。

### 26. 下列哪种集合运算会返回两个关系中所有的元组并去重（把重复行合并为一条）？

- **A. UNION (正确)**
- B. UNION ALL
- C. EXCEPT ALL
- D. INTERSECT

> **【选项解析】**：标准 `UNION` 就是执行合并加去重；`UNION ALL` 合并但不去重；`INTERSECT` 是交集。
>
> **【知识点扩展】**：由于去重涉及全量排序去重，在确定两个结果集物理上不会有重叠，或者业务上允许重复出现时，使用 `UNION ALL` 的效率更高。

### 27. 如果想查找各部门的讲师平均薪水，但只返回平均薪水大于 42000 的部门，应使用哪一条 SQL 语句？

- A. SELECT dept_name, AVG(salary) AS avg_salary FROM instructor GROUP BY dept_name WHERE AVG(salary) > 42000;
- **B. SELECT dept_name, AVG(salary) AS avg_salary FROM instructor GROUP BY dept_name HAVING AVG(salary) > 42000; (正确)**
- C. SELECT dept_name, AVG(salary) AS avg_salary FROM instructor HAVING AVG(salary) > 42000 GROUP BY dept_name;
- D. SELECT dept_name, AVG(salary) AS avg_salary FROM instructor WHERE AVG(salary) > 42000 GROUP BY dept_name;

> **【选项解析】**：基于聚合后的结果组进行条件过滤，必须用 `HAVING` 子句，且 `HAVING` 必须写在 `GROUP BY` 的后方。
>
> **【知识点扩展】**：这是一个极其经典的考点。一定要区分 `WHERE`（筛选哪些人可以参与计算）和 `HAVING`（筛选算完以后哪个组的结果达标）。

### 28. 下列关于分组聚合的描述，哪一项是正确的？

- A. GROUP BY 仅在 FROM 子句中定义的表之间起作用,与 SELECT 的列无关。
- B. 聚合函数只能对单列使用,不能对多列使用。
- **C. 聚合函数之外的 SELECT 子句中的属性必须出现在 GROUP BY 子句中。 (正确)**
- D. GROUP BY 子句不能与 HAVING 子句共存。

> **【选项解析】**：如果在 SELECT 中出现了诸如 `ID`, `Name` 等没有被聚合函数包裹的属性，引擎无法抉择该返回哪个具体行的值，因此未聚合列必须做分组键。
>
> **【知识点扩展】**：这反映了 SQL 在处理多对一映射时的确定性原则。任何导致多值歧义的语法都会在编译阶段被拦截。

### 29. 要查找不在给定薪资集合中的讲师，可以使用哪种？

### 34. 哪种聚合函数生成排名而不留空缺？

### 43. 在关系数据库设计中，通常要避免什么问题？

- C. 复合键索引
- D. 稀疏索引

> **【选项解析】**：A 哈希索引适合等值查找，但不专门表示“允许重复键”；C 复合键索引用于多个属性联合检索；D 稀疏索引只保存部分搜索键值。B 正确，非唯一键索引允许多个记录共享同一个搜索键值。
>
> **【知识点扩展】**：当搜索键不是候选键时，一个键值可能对应多条记录。非唯一索引通常通过重复的键-指针对、记录标识符，或指向指针列表/桶的方式定位所有匹配记录。

### 53. 在 B+ 树中，每个节点的搜索键的最大及最小数量分别是什么？

- A. 根节点至少 1 个，其他节点在 1 到 n 之间
- B. 每个节点至少 3 个
- **C. 根节点至少 2 个，其他节点在 $\lceil n/2 \rceil$ 和 n 之间 (正确)**
- D. 根节点必须只有一个

> **【选项解析】**：A 没有体现 B+ 树节点至少半满的约束；B 把最小数量固定为 3，不符合阶数参数化定义；D 错在根节点不必只有一个搜索键。C 正确，非根节点通常要求至少半满，根节点有单独的下限约束。
>
> **【知识点扩展】**：B+ 树通过“节点容量上限 + 非根节点至少半满 + 所有叶节点同层”来维持平衡。这样可以保证查找、插入和删除的复杂度都保持在对数级别。

### 54. 向 B+ 树插入新记录时，若叶节点已满，接下来的步骤是什么？

- A. 直接丢弃记录
- B. 修改现有节点
- C. 无需任何更改
- **D. 对叶节点进行拆分并更新父节点 (正确)**

> **【选项解析】**：A 会造成数据丢失；B 说法过于笼统，不能解决节点溢出；C 错在叶节点已满时必须处理容量问题。D 正确，满叶节点插入时需要分裂，并把分裂产生的分隔键向父节点传播。
>
> **【知识点扩展】**：B+ 树插入可能触发级联分裂：叶节点分裂后父节点如果也满，则继续向上分裂，必要时产生新的根节点，从而增加树高。

### 55. 以下哪种数据模型通常用于存储复杂数据？

- A. 实体关系模型
- B. 关系模型
- C. 层次模型
- **D. 半结构化数据 (正确)**

> **【选项解析】**：A 主要用于概念设计；B 关系模型要求较固定的表结构；C 层次模型表达能力较受树形结构限制。D 正确，半结构化数据适合表达嵌套、可变字段和结构不完全一致的数据。
>
> **【知识点扩展】**：半结构化数据常见格式包括 JSON、XML、键值文档和宽列模型。它不要求所有记录拥有完全相同的属性集合，因此常用于复杂对象、日志、配置和 Web 数据交换。

### 56. JSON 数据中，如何表示一个对象？

- A. 使用 XML 标签
- **B. 使用键值对的形式 (正确)**
- C. 使用列表
- D. 使用数组

> **【选项解析】**：A 是 XML 的表示方式；C 和 D 更接近数组或列表结构，而不是对象的核心表示。B 正确，JSON 对象由花括号包围的一组键值对构成。
>
> **【知识点扩展】**：JSON 对象形如 `{"name": "Alice", "age": 20}`，键通常是字符串，值可以是字符串、数字、布尔值、数组、对象或 `null`。这种结构天然适合表示半结构化数据。

### 57. 关于空间数据，下列哪个描述是错误的？

- A. 可以存储复杂的几何形状
- B. 空间数据支持高效存储和索引
- C. 空间查询可以包含查找相邻数据
- **D. 空间数据只能是二维的 (正确)**

> **【选项解析】**：A、B、C 都是空间数据库的常见能力；D 错在“只能是二维”，空间数据可以表示二维、三维甚至更高维的地理或几何对象。题目问错误描述，因此 D 为正确选项。
>
> **【知识点扩展】**：空间数据库常用 R-tree、GiST 等索引结构支持范围查询、最近邻查询、相交判断和包含判断。典型数据包括点、线、多边形、路线和三维对象。

### 58. XML 什么特性使其数据具有自文档性？

- A. 使用线性结构
- B. 使用简单文本
- C. 使用列表
- **D. 使用标签标记文本 (正确)**

> **【选项解析】**：A、B、C 都不能说明 XML 为什么能自描述；D 正确，XML 通过标签给数据片段命名，使数据的含义与结构直接写在文档中。
>
> **【知识点扩展】**：XML 的标签既描述数据结构，也表达语义。例如 `<student><name>Kim</name></student>` 中，标签直接说明了字段含义，因此即使没有外部表结构，也能理解数据内容。

### 59. 在 B+ 树索引中，为了保证平衡性（Balance），以下哪个性质是必需的？

- A. 所有内部节点都必须恰好有 $\lceil n/2 \rceil$ 个子节点。
- **B. 从根节点到任何叶节点的路径长度（即树的层高）必须是相同的。 (正确)**
- C. 所有叶节点上的搜索键值都必须是唯一的。
- D. 所有内部节点和叶节点都必须有相同的最大容量。

> **【选项解析】**：A 错在节点不要求“恰好”半满，只需满足上下界；C 错在 B+ 树可以处理重复搜索键；D 不是保证平衡性的必要条件。B 正确，所有叶节点位于同一层是 B+ 树保持平衡查找路径的关键。
>
> **【知识点扩展】**：B+ 树的平衡性意味着任意一次从根到叶的查找都经过相同层数，因此性能稳定。插入和删除时的分裂、合并或重分配都是为了维持这种结构性质。

### 60. 在稀疏索引中，索引条目通常是？

- A. 唯一搜索键的记录
- **B. 部分搜索键值的记录 (正确)**
- C. 所有搜索键值的记录
- D. 聚合数据的记录

> **【选项解析】**：A 把稀疏索引与唯一性混淆；C 描述的是稠密索引；D 与索引条目的定义无关。B 正确，稀疏索引只为部分搜索键值建立索引条目。
>
> **【知识点扩展】**：稀疏索引通常要求数据文件按搜索键有序存储，每个索引项指向一个数据块或某个范围的起始位置。它比稠密索引更省空间，但定位后可能还需要在数据块内继续扫描。

### 61. 在 B+ 树结构中，如何处理具有相同搜索键值的多条数据记录？

- **A. 每条重复的记录在叶节点中有一个单独的索引条目（Key-Pointer Pair）。 (正确)**
- B. 这些重复记录只能通过聚簇索引来存储。
- C. 只存储一个搜索键条目，并指向一个包含所有重复记录指针的溢出块。
- D. B+ 树要求搜索键值必须是唯一的，不允许重复。

> **【选项解析】**：B 错在重复键并不只能依赖聚簇索引；C 是一种可能的变体，但本题所问的 B+ 树结构通常用多个键-指针对表示重复键；D 错在搜索键不一定是候选键。A 正确，重复搜索键可以在叶节点中对应多个记录指针。
>
> **【知识点扩展】**：为了区分重复搜索键，实际系统常把记录 ID 与搜索键组合，形成逻辑上唯一的索引项。这样既保留 B+ 树的有序性，也能定位同一键值下的多条记录。

### 62. 在 B+ 树的更新（删除）操作中，如何处理节点过少的情况？

- A. 重新分配记录
- **B. 进行兄弟节点合并 (正确)**
- C. 只更新父节点
- D. 直接删除节点

> **【选项解析】**：A 重新分配是处理下溢的一种方式，但本题给出的正确处理是与兄弟节点合并；C 只更新父节点不能恢复节点容量约束；D 直接删除会破坏树结构。B 正确，节点过少时可与兄弟节点合并并调整父节点分隔键。
>
> **【知识点扩展】**：B+ 树删除后的下溢处理通常有两类：向兄弟节点借记录（redistribution）或与兄弟节点合并（coalescence）。若合并导致父节点下溢，调整可能继续向上递归。

### 63. 测试一个并发调度是否可冲突串行化时，如果优先关系图存在环路，该调度是否可冲突串行化？

- **A. 否 (正确)**
- B. 需要额外信息才能判断
- C. 是
- D. 只有在特定情况下才否

> **【选项解析】**：B 错在优先关系图已经足以判断冲突可串行化；C 与判定定理相反；D 错在只要存在环就不满足冲突可串行化。A 正确，优先图有环说明事务之间存在循环依赖。
>
> **【知识点扩展】**：冲突可串行化的判定方法是构造优先图（precedence graph）。若图无环，则存在一个拓扑序，对应等价的串行调度；若图有环，则不存在这样的串行顺序。

### 64. 在并发控制中，哪种可串行化定义确保调度与某个串行调度等价且以冲突为基础进行分析？

- A. 全局锁串行化
- B. 视图可串行化
- **C. 冲突可串行化 (正确)**
- D. 无冲突不可串行化

> **【选项解析】**：A 不是标准的可串行化分类；B 视图可串行化基于读写来源和最终写入等视图等价；D 表述本身不成立。C 正确，冲突可串行化通过冲突操作的相对顺序来判断是否等价于某个串行调度。
>
> **【知识点扩展】**：两个操作若来自不同事务、访问同一数据项且至少一个是写操作，就构成冲突。冲突可串行化要求通过交换非冲突操作，能把调度转换为某个串行调度。

### 65. 如果某一事务的提交在另一个事务尚未提交之前进行，且该后续事务读取了前者写入的数据，这样的调度属于哪种可恢复性概念？

- A. 无级联调度
- B. 可串行化调度
- **C. 可恢复调度 (正确)**
- D. 级联回滚

> **【选项解析】**：A 无级联调度要求事务只读取已经提交的数据，比可恢复调度更强；B 可串行化关注并发执行结果是否等价于串行执行，不直接描述提交顺序的恢复性；D 级联回滚描述的是读取了未提交数据后，写入事务回滚导致读取事务也必须回滚的现象。C 正确，可恢复调度要求如果事务读取了另一个事务写入的数据，则写入者必须先于读取者提交。
>
> **【知识点扩展】**：可恢复性关注故障时是否会出现“已提交事务依赖未提交事务”的问题。可恢复调度允许读取未提交数据，但要求被读取的事务先提交；无级联调度则进一步禁止读取未提交数据。
